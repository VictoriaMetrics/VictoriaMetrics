This page describes the VictoriaMetrics metrics that are referenced by the [bundled alerting rules](https://github.com/VictoriaMetrics/VictoriaMetrics/tree/master/deployment/docker/rules). Use it to understand what a metric means when it shows up in an alert.

The page does not list every metric a component exposes, and it is not generated automatically. You can find the full list of metrics for each component at the `/metrics` page. See [monitoring](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#monitoring) for how to reach it.

Sections are named after the cluster components. Single-node VictoriaMetrics runs the same code in one process, so it exposes the vmstorage, vminsert and vmselect metrics from a single binary.

`vmanomaly` metrics are not listed here. See [metrics generated by vmanomaly](https://docs.victoriametrics.com/anomaly-detection/components/monitoring/#metrics-generated-by-vmanomaly) for them.

## vmstorage

| Metric | Description |
|---|---|
| `vm_data_size_bytes` | Current size of stored parts in bytes, in memory and on disk, split by the `type` label, for example `storage/inmemory`, `storage/small`, `storage/big` or `indexdb/file`. |
| `vm_free_disk_space_bytes` | Current free disk space on the `-storageDataPath` filesystem, in bytes. |
| `vm_free_disk_space_limit_bytes` | Configured minimum free disk space set by `-storage.minFreeDiskSpaceBytes`, below which vmstorage switches to read-only, in bytes. |
| `vm_indexdb_items_dropped_total` | Total number of indexdb records that could not be registered during ingestion, split by the `reason` label. |
| `vm_metrics_metadata_storage_max_size_bytes` | Configured maximum size in bytes of the in-memory metrics-metadata storage. |
| `vm_metrics_metadata_storage_size_bytes` | Current size in bytes used by the in-memory metrics-metadata storage. |
| `vm_missing_tsids_for_metric_id_total` | Total number of times a metric ID had no corresponding TSID entry in indexdb during query resolution. |
| `vm_new_timeseries_created_total` | Total number of brand-new time series created in storage (TSID generated because the series was not found in any indexdb). |
| `vm_rows` | Current number of rows stored in parts, split by the `type` label: `storage/inmemory`, `storage/small` and `storage/big` for datapoints, `indexdb/inmemory` and `indexdb/file` for index items. |
| `vm_rows_added_to_storage_total` | Total number of rows actually added to storage parts since startup, after dropping out-of-retention and invalid rows. |
| `vm_slow_row_inserts_total` | Total number of inserted rows that missed the TSID cache and required an indexdb lookup or new-series creation (a slow insert). |

## vminsert

| Metric | Description |
|---|---|
| `vm_rows_inserted_total` | Total number of rows submitted for insertion into storage, split by the `type` label holding the ingestion protocol. |
| `vm_rpc_connection_errors_total`&nbsp;\* | Total number of errors on established connections to a vmstorage node (send and ack failures), split by the `addr` and `rpc_call` labels. |
| `vm_rpc_dial_errors_total`&nbsp;\* | Total number of failed TCP dial attempts to a vmstorage node, split by the `addr` and `rpc_call` labels. |
| `vm_rpc_handshake_errors_total`&nbsp;\* | Total number of failed vminsert to vmstorage protocol handshakes after a successful TCP connect, split by the `addr` and `rpc_call` labels. |
| `vm_rpc_send_duration_seconds_total`&nbsp;\* | Total seconds spent sending data to a vmstorage node, split by the `addr` and `rpc_call` labels. |

\* Available only in the cluster version.

## vmselect

| Metric | Description |
|---|---|
| `vm_concurrent_select_limit_timeout_total` | Total number of search requests rejected with HTTP 429 (Too Many Requests) after waiting for a concurrency slot without getting one in time. |

## vmagent

| Metric | Description |
|---|---|
| `vm_persistentqueue_bytes_dropped_total` | Total number of bytes dropped from the on-disk remote-write queue because it exceeded the `-remoteWrite.maxDiskUsagePerURL` limit. |
| `vm_persistentqueue_bytes_pending` | Current number of bytes pending in the on-disk remote-write queue, waiting to be sent to remote storage. |
| `vm_persistentqueue_free_disk_space_bytes` | Current number of bytes the on-disk remote-write queue can still grow before hitting its capacity limit. |
| `vm_persistentqueue_read_duration_seconds_total` | Total time in seconds spent reading blocks from on-disk remote-write queues, used as a read-saturation signal. |
| `vm_persistentqueue_write_duration_seconds_total` | Total time in seconds spent writing blocks to on-disk remote-write queues, used as a write-saturation signal. |
| `vm_streamaggr_dedup_flush_timeouts_total` | Total number of times a deduplication-state flush could not complete within the configured `dedup_interval`. |
| `vm_streamaggr_flush_timeouts_total` | Total number of times an aggregation-state flush could not complete within the configured `interval`. |
| `vmagent_daily_series_limit_current_series` | Current number of unique series registered during the last day, as tracked by the `-remoteWrite.maxDailySeries` limiter. |
| `vmagent_daily_series_limit_max_series` | Configured daily unique-series limit set via `-remoteWrite.maxDailySeries`. |
| `vmagent_hourly_series_limit_current_series` | Current number of unique series registered during the last hour, as tracked by the `-remoteWrite.maxHourlySeries` limiter. |
| `vmagent_hourly_series_limit_max_series` | Configured hourly unique-series limit set via `-remoteWrite.maxHourlySeries`. |
| `vmagent_http_request_errors_total` | Total number of failed vmagent HTTP requests on ingestion endpoints and the `/target_response` helper endpoint. |
| `vmagent_relabel_config_last_reload_successful` | Whether the last reload of the remote-write relabel configs succeeded (1) or failed (0). |
| `vmagent_remotewrite_packets_dropped_total` | Total number of data blocks dropped after the remote storage rejected them with 400 Bad Request, 409 Conflict or 415 Unsupported Media Type, split by the `url` label. |
| `vmagent_remotewrite_pending_data_bytes` | Current bytes pending in the in-memory and on-disk remote-write queue, not yet sent to remote storage. |
| `vmagent_remotewrite_queues` | Number of concurrent send worker connections set by `-remoteWrite.queues` for the remote storage, split by the `url` label. |
| `vmagent_remotewrite_retries_count_total` | Total number of retries of block sends to the remote storage, split by the `url` label. |
| `vmagent_remotewrite_send_duration_seconds_total` | Total seconds spent by all send workers sending blocks to the remote storage, split by the `url` label. |

## vmauth

| Metric | Description |
|---|---|
| `vmauth_concurrent_requests_limit_reached_total` | Total number of requests rejected with HTTP 429 because the global `-maxConcurrentRequests` limit could not be acquired within `-maxQueueDuration`. |
| `vmauth_http_request_errors_total` | Total number of requests vmauth failed to route, split by the `reason` label: `invalid_auth_token`, `missing_route`, `client_canceled` or `reject_slow_client`. |
| `vmauth_unauthorized_user_concurrent_requests_limit_reached_total` | Total number of `unauthorized_user` requests rejected with HTTP 429 because the section's per-user concurrency limit could not be acquired within `-maxQueueDuration`. |
| `vmauth_unauthorized_user_request_errors_total` | Total number of `unauthorized_user` requests that failed from the client's perspective in vmauth (no backend served them successfully). |
| `vmauth_user_concurrent_requests_limit_reached_total` | Total number of requests for the given `username` rejected with HTTP 429 because the per-user concurrency limit could not be acquired within `-maxQueueDuration`. |
| `vmauth_user_request_errors_total` | Total number of requests for the given `username` that failed from the client's perspective in vmauth (no backend served them successfully). |

## vmalert

| Metric | Description |
|---|---|
| `vmalert_alerting_rules_errors_total` | Total number of errors while evaluating alerting rules. |
| `vmalert_alerting_rules_last_evaluation_samples` | Number of samples produced by an alerting rule's last evaluation. |
| `vmalert_alerts_send_errors_total` | Total number of alerts that failed to be sent to the notifier. |
| `vmalert_config_last_reload_successful` | Whether the last configuration reload was successful (1) or not (0). |
| `vmalert_iteration_missed_total` | Total number of evaluation ticks where one or more iterations were skipped because the previous evaluation overran the interval. |
| `vmalert_iteration_reset_total` | Total number of times a group's evaluation schedule was reset to the current time. |
| `vmalert_recording_rules_errors_total` | Total number of errors while evaluating recording rules. |
| `vmalert_recording_rules_last_evaluation_samples` | Number of samples produced by a recording rule's last evaluation. |
| `vmalert_remotewrite_dropped_rows_total` | Total number of rows (samples) dropped before being written to the remote-write URL. |
| `vmalert_remotewrite_errors_total` | Total number of errors that occurred while sending data to the remote-write URL. |
| `vmalert_remotewrite_queue_capacity` | Configured maximum capacity of the remote-write queue in number of time series, set by `-remoteWrite.maxQueueSize`. |
| `vmalert_remotewrite_queue_size` | Number of time series pending in the remote-write queue, sampled at each flush (histogram). |
| `vmalert_rule_group_results_limit` | Effective limit on the number of results a single rule in the group may produce, set by `-rule.resultsLimit` or by the group's own `limit` option. 0 means no limit. |

## vmbackupmanager

| Metric | Description |
|---|---|
| `vm_backup_last_success_at` | Unix timestamp in seconds of the last successful backup, split by the `type` label: `latest`, `hourly`, `daily`, `weekly` or `monthly`. Stays 0 until the first backup of that type succeeds after start. Available from v1.149.0. |

## Common metrics

Exposed by several components through shared libraries.

| Metric | Description |
|---|---|
| `vm_app_uptime_seconds` | Number of seconds since the process started. A drop in this value means the process restarted. |
| `vm_available_memory_bytes` | Current total amount of memory in bytes available to the process (min of host RAM and cgroup limit). |
| `vm_cache_entries` | Current number of entries held in an in-memory cache, split by the `type` label identifying the cache. |
| `vm_cache_size_bytes` | Current size in bytes of an in-memory cache, split by the `type` label identifying the cache. |
| `vm_cache_size_max_bytes` | Maximum allowed size in bytes of an in-memory cache, split by the `type` label identifying the cache. |
| `vm_concurrent_insert_capacity` | Maximum number of concurrent insert requests allowed, that is the value of the `-maxConcurrentInserts` flag. |
| `vm_concurrent_insert_current` | Current number of in-flight concurrent insert requests holding a slot in the limiter. |
| `vm_deduplicated_samples_total` | Total number of samples dropped by deduplication, split by the `type` label: `select` for in-flight deduplication during reads, `merge` for permanent deduplication during background merges. |
| `vm_http_request_errors_total` | Total number of HTTP requests that returned an error, split by the `path` and `reason` labels. |
| `vm_ingestserver_request_errors_total` | Total number of failed write requests on the TCP and UDP ingestion listeners, split by the `type`, `name` and `net` labels. |
| `vm_log_messages_total` | Total number of log messages emitted, split by the `level`, `location`, `app_version` and `is_printed` labels. |
| `vm_promscrape_config_last_reload_successful` | Whether the last scrape configuration reload succeeded: 1 if successful, 0 if it failed. |
| `vm_promscrape_scrape_pool_targets` | Current number of targets in a scrape pool, split by the `scrape_job` and `status` labels, where `status` is `up` or `down`. |
| `vm_promscrape_scrapes_failed_total` | Total number of failed scrapes (scrape and transport errors, plus parse errors in stream-parse mode). |
| `vm_rows_ignored_total` | Total number of rows or series ignored during ingestion or scrape, split by the `reason` label. |

## Runtime metrics

Go runtime metrics (`go_*`) are exported by every component via the [`github.com/VictoriaMetrics/metrics`](https://github.com/VictoriaMetrics/metrics) library as a mirror of the Go [`runtime/metrics`](https://pkg.go.dev/runtime/metrics) package. See the Go documentation for their descriptions.

| Metric | Description |
|---|---|
| `process_cpu_cores_available` | Current number of CPU cores available to the process, respecting both logical CPUs and the cgroup CPU quota. |
| `process_cpu_seconds_total` | Total user and system CPU time consumed by the process, in seconds. |
| `process_max_fds` | Soft limit on the number of file descriptors the process may open, read from `/proc/self/limits`. |
| `process_open_fds` | Current number of open file descriptors. |
| `process_resident_memory_anon_bytes` | Anonymous resident memory of the process, that is RSS without file-backed pages, in bytes. |
| `process_resident_memory_bytes` | Resident memory size (RSS) of the process, in bytes. |
| `process_start_time_seconds` | Unix timestamp, in seconds, at which the process started. |
